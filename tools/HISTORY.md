# 这套库是怎么做出来的（质量记录）

这套笔记的价值不只是"写完了"，而是**每一句都被人（独立代理）重算过**。这里记录可复现的过程与数据。

## 一、三层结构

```
数据层      tools/dc.js · matrices.js · vectors.js · equations.js · eigen.js · quadratic.js
            ← 每个知识点一个对象：id / 标题 / 标签（基础·数一·数二）/ 一句话 / 关系边
            tools/edges.js            ← 164 条关系边（源、目标、类型、一句数学含义）
通俗层      tools/deep-v2/_draft/*.md  ← 103 篇正文草稿（痛点/坑/补上/细节/用法/自测）
            tools/deep-v2/m-*.json     ← 由 draft2json.mjs 校验后转换
产物层      node tools/build.js <输出>       → 103 篇笔记 + 7 章节页 + 4 汇总页
            node tools/canvas-v2.js <输出>   → 6 张 Canvas 关系图
```

## 二、写作规范（tools/deep-v2/SPEC-写作规范.md 的 7 条硬规则）

1. **概念依赖**：引入段只能用已经讲过的概念；不得出现后面章节的术语（有可执行校验）
2. **编号一致**：三条坑必须编号，且"逐条补上"里的每一条都要对上号（不得悬空引用）
3. **不得循环论证**：不能用"待建立的结论"去证明它自己
4. **每个断言都要能独立复算**：正文里的算例必须能被脚本重算出来
5. **LaTeX 规范**：矩阵用 `pmatrix`、`$$` 独占一行、公式里不写中文
6. **语气与长度**：口语化；"一句话"视觉宽度 ≤ 46
7. **每次改动都跑校验套件**

## 三、语料规模

- 103 个知识点，7 章 + 1 个附录
- 164 条关系边（充要 31 / 充分 59 / 必要 55 / 关联 17 / 无关 2）
- 每篇正文约 1500–3000 字，合计约 20 万字

## 四、正确性是怎么保证的

### 1. 八轮独立审校（每个知识点都被重算过）

写手写完不算完，另有独立代理**不看结论、只重算**：它用精确有理数算术（BigInt）自写 rref、行列式、特征值求解，把正文里每个算例、每个反例、每个前提条件都验一遍。

| 章节 | 篇数 | 审校重算断言 | 查出问题 | 其中高危 |
| --- | --- | --- | --- | --- |
| 行列式 | 17 | 194 | 10 | 1 |
| 矩阵（a+b 片） | 14 | 170 + 穷举 19683 个 3 阶矩阵 | 13 | 1 |
| 矩阵（c+d 片） | 13 | 21 组 + 穷举 2.7 万个矩阵对 | 17 | 0 |
| 向量 | 13 | 163 + 16 万组随机 | 8 | 0 |
| 方程组 | 12 | 68 | 6 | 0 |
| 特征值 | 17 | 94 | 4 | 1 |
| 二次型 | 11 | 166 | 17 | 7 |
| 附录 | 6 | 60 | 7 | 0 |
| **合计** | **103** | **约 940 条 + 数十万次穷举/随机** | **82** | **10** |

**10 处高危**都是"照着做会做错"的类型，例如：

- 某篇自测给出的求逆公式只对它自己那个矩阵成立，读者一代入就得到错的逆
- 特征值估计里三次方程的根写成 `(9±√33)/2`，真值是 `3±√3`（而同一篇的近似值恰好是对的，所以很难发现）
- 二次型章 7 处：正交变换的 `Q` 印错（与四处验算互相矛盾）、两处 `CᵀAC` 算错、特征多项式属于另一个矩阵、`diag(0,-1)` 被叫"负定"、把**正确**的公式当成"写错了"
- 三对角行列式那篇写"上下斜线符号相反时常是周期数列"——实测只有 `a=0` 是周期，`a=1` 就是斐波那契

### 2. 关系边的语义审计（逐条"反过来读"）

关系边会渲染成笔记正文里的一句话，例如「本点 ⇒ 对方 ｜ 必要不充分（⇐）」读作"**本点是对方的必要条件**"。所以：

- `iff` 必须**两个方向**都真
- `suff` / `need` 必须只有单向成立，且方向正确
- `rel` 绝不能读成条件关系

审计复算了 103 篇笔记的关系表（当时的 163 条边 × 2 个方向 = 326 行逐字命中）后逐条判读，修正 11 处，包括：

- 3 处假 `iff`（如"三角行列式 ⇔ 化三角形"其实是过程与终点公式的关系）
- 1 处反向 `suff`（"三对角 → 展开定理"，实际是展开定理 → 三对角）
- 1 对互为反向且类型矛盾的边（`正交对角化 ↔ 正交变换法`，一边写 suff 一边写 need）
- 2 处重复边（同一对知识点双向并存且依赖方向相反）

> 顺带一提：审计代理自己也把"必要/充分"的方向读反过一批，被逐条复核驳回 —— 规则是**谁的数字都要能复算**，不是"审校说的就算"。

### 3. 可执行的检查（每次改动都跑）

```

check-template.mjs            103 篇是否都符合叙事骨架 + 关系网是否可折叠
check-links.mjs               所有双链可解析（当前 2164 条 wikilink + 424 条普通链接）
check-mislinks.mjs            矩阵记号不会被误判成双链
check-contain.mjs             Canvas 节点不越界
check-oneline.mjs             "一句话"视觉宽度 ≤ 46
check-jargon.mjs              引入段术语越界（可失败性经过反例验证）
```

## 五、几个踩过的坑（留作记录）

- **文件名安全化**：一开始把所有非法字符统一替换成下划线，导致 `A*` 变成 `A＿`、文件名不可读 → 改为各自替换成合法的形近字符（`*`→`∗`、`/`→`／`）
- **折叠失效**：`<details>` 是 HTML 块，遇到空行就结束，里面的表格跑到块外 → 折叠框是空的、点了没反应；改用 Obsidian 原生可折叠 callout
- **生成器覆盖写**：用 `--ids` 只改一部分知识点时，写回把文件里其余知识点冲掉了（丢过 5 个点）→ 改成合并写回并打印"保留原有 N 个"
- **改名残留**：重命名笔记后旧文件残留在库里 → 加了"知识点 ID 不得重复"的校验护栏，专治这种残留
- **连通性**：一度有 4 个知识点互相连但整体孤立（另有 1 个完全孤立）→ 补 13 条关系边 + 让每篇笔记都带一条"章节"边（结构保险）

## 六、v1.1 修掉的几件事（相对 v1.0）

- **补上"可交换 ⇒ 特征向量共享"这条定理**：原先全库（103 篇 + 关系边）都没有它。现在作为**性质四**写进 `特征值与特征向量的性质`，并在 `AB ≠ BA（乘法不可交换）` 与它之间加了一条关联边（**163 → 164 条**）。验证用精确有理数（BigInt 分数）：与 A 可交换的矩阵解空间维数 = n、解空间里任意 B 都保持 A 的特征向量；重根时给反例（$A=\mathrm{diag}(1,1,2)$，B 把 $e_2$ 换成 $e_1+e_2$）。顺带修正本文下一节里的一处算错（"163 条边 × 2 个方向 = 330 行"，应为 326 行）。
- **图谱设置被运行中的 Obsidian 覆盖**：`.obsidian/graph.json` 里那三个节点配色组（`tag:#基础` / `tag:#数一` / `tag:#数二`）和 `showArrow` 是手写进去的，但 Obsidian 开着的时候会用内存里的状态把它覆盖回默认值 —— 结果发布包里"开箱就有配色和箭头"这句话差点不成立。现在加了 `check-graph-config.mjs`：发布前检查配色组、箭头开关、插件连线着色配置，以及暂存区与 vault 是否一致。
- **HTML 标签里不解析 Markdown**：色条标签原先是 `<span class="pit">**坑一…**</span>` 这种"把文字包进 HTML 标签"的写法，而 Obsidian 不解析标签内部的 Markdown，于是这些段落的加粗和 `$行内公式$` 全变成纯文本（影响 1200 多处）。现在标签里只放一个零宽标记（U+200B），文字仍在 Markdown 层，配色改由 CSS 兄弟选择器 `span.pit + strong` 完成 —— 既保住"只有标题变色"，又让加粗与公式正常渲染。
- **主元列不一定在前 r 列**：`极大线性无关组` 那篇原来只说"记下主元所在列号"，读者容易直接取前 `r` 个向量。补了反例（$c_2=2c_1$ ⇒ 主元在第 1、3 列）并写进易错点。
- **两处特征多项式的补充**：展开后 $\lambda$ 与 $x_i$ 是相乘关系（所以它不是线性方程组）、以及 $|A-\lambda E|=(-1)^n|\lambda E-A|$。
- **校验脚本的白名单抄了两份**：`check-latex.mjs` 自己抄的 AMS 命令表比共享的 `latexcheck.mjs` 旧，把 `\xrightarrow` 误判成"未知命令"→ 现在统一从 `latexcheck.mjs` 取名单，并做了反例验证（`\xyzw` 仍然会报错）。
- **ZIP 内部路径分隔符**：.NET 的 `ZipFile::CreateFromDirectory` 在 Windows 上把分隔符写成反斜杠（不符合 ZIP 规范），macOS / Linux 解压会得到 `.obsidian\app.json` 这种文件名 → 改为自写的规范打包器（deflate + 正斜杠 + UTF-8 名字标记），并逐项校验 CRC 与解压结果。
- **增量发布**：发布脚本原先只能"从零建仓库"，现在 `publish-update.mjs` 先算本地 git blob sha 与远端树对比，只上传真正变化的文件（本次 145 个 / 全库 285 个），提交接在 main 之后。
- **Release 说明的编码**：v1.0 的 Release 说明当年是被写坏的（950 字里有 483 个乱码问号），v1.1 起一律用 Node 以 UTF-8 写入，并回头修好了 v1.0 的说明。
